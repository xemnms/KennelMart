# KennelMart — Vibe Coding Context & OOP Implementation Guide

## Project Identity

### App Name

KennelMart

### System Type

Campus-based marketplace platform for National University Laguna students and faculty.

### Core Purpose

Provide a secure and moderated marketplace where verified NU users can:

* Buy products/services
* Sell products/services
* Manage orders
* Communicate safely within campus

# OOP Principles Implementation Guide

# 1. Encapsulation

## Vibe

Protect internal data.

## Rules

* all entity fields must be private
* use getters/setters
* validate sensitive updates

## Example Use

```java
private String password;
```

---

# 2. Abstraction

## Vibe

Hide complexity behind clean interfaces.

## Rules

* use interfaces for services
* expose behavior, not implementation

## Example

```java
interface OrderService
```

---

# 3. Composition Over Inheritance

## Vibe

Assemble behavior instead of forcing hierarchies.

## Preferred

```java
Order has OrderItems
```

## Avoid

Deep inheritance chains.

---

# 4. Single Responsibility Principle (SRP)

## Vibe

One class = one responsibility.

## Good

```text
AuthService
ProductService
OrderService
```

## Bad

```text
MarketplaceManager
```

---

# 5. Separation of Concerns

## Vibe

Every layer has a clear job.

---

## Controller

Handles HTTP requests/responses.

## Service

Handles business logic.

## Repository

Handles database access.

## DTO

Transfers safe data.

---

# 6. Interface-Based Design

## Vibe

Depend on contracts, not implementations.

## Example

```java
PaymentStrategy paymentStrategy;
```

---

# 7. Low Coupling

## Vibe

Classes should not heavily depend on each other.

## Preferred

Use dependency injection.

```java
OrderService(PaymentService paymentService)
```

---

# 8. High Cohesion

## Vibe

Related logic stays together.

## Example

`OrderService`
ONLY handles:

* order processing
* status updates
* order validation

---

# 9. Layered Architecture

## Vibe

Strict architectural boundaries.

## Rule

Controllers NEVER directly access repositories.

---

# 10. Dependency Injection

## Vibe

Spring manages dependencies.

## Preferred

Constructor injection.

```java
@RequiredArgsConstructor
```

---

# 11. DTO Pattern

## Vibe

Never expose entities directly.

## Required DTOs

```text
ProductRequestDTO
ProductResponseDTO
OrderResponseDTO
```

---

# 12. Strategy Pattern

## Vibe

Replace condition-heavy logic.

## Best Use Cases

* payment methods
* notification channels
* delivery options

---

# 13. Factory Pattern

## Vibe

Centralized object creation.

## Best Use Cases

* listing creation
* notification builders

---

# 14. Observer Pattern

## Vibe

Automatic event notifications.

## Best Use Cases

* order updates
* seller notifications
* admin alerts
