# KennelMart — Low-Level Requirements (MVP First)

## 1. Project Goal

Build a campus-only marketplace platform for the National University Laguna community where verified students and faculty can safely buy and sell products/services.

The MVP should prioritize:

1. Secure account registration/login
2. Identity verification
3. Product listing management
4. Product browsing
5. Cart and ordering
6. Order tracking
7. Basic admin moderation

Everything else should support those workflows.

---

# 7. MVP Scope Prioritization

# PHASE 1 — FOUNDATION (Critical)

## 7.1 Authentication Module

### Features

* Register
* Login
* JWT Authentication
* Password hashing
* Role assignment

### Backend Requirements

#### APIs

```http
POST /api/auth/register
POST /api/auth/login
GET  /api/auth/me
```

### Validation Rules

* NU email required
* Password minimum 8 chars
* Email uniqueness

### Acceptance Criteria

* User can create account
* User can login
* JWT returned successfully

---

## 7.2 Identity Verification

## Goal

Only verified NU Laguna users can transact.

### Requirements

* Upload student/faculty ID
* Compare against sample SQL database
* Admin approval flow

### Tables

```java
VerifiedIdentity
- schoolId
- fullName
- email
```

### APIs

```http
POST /api/verification/submit
GET  /api/verification/status
PUT  /api/admin/verification/{id}/approve
PUT  /api/admin/verification/{id}/reject
```

### MVP Simplification

* Manual admin approval
* No OCR/image recognition

---

# PHASE 2 — MARKETPLACE CORE (Critical)

## 7.3 Product Listing Management

### Seller Features

* Create listing
* Edit listing
* Delete listing
* Upload images
* Set stock quantity

### APIs

```http
POST   /api/listings
PUT    /api/listings/{id}
DELETE /api/listings/{id}
GET    /api/listings/my-listings
```

### Validation Rules

* Price > 0
* Stock >= 0
* Minimum 1 image

---

## 7.4 Browse Marketplace

### Buyer Features

* View listings
* Search
* Filter by category
* View seller profile

### APIs

```http
GET /api/listings
GET /api/listings/{id}
GET /api/users/{id}
```

### Sorting

* Latest
* Lowest price
* Highest price

---

## 7.5 Cart System

### Features

* Add to cart
* Remove item
* Adjust quantity

### APIs

```http
POST   /api/cart/items
PUT    /api/cart/items/{id}
DELETE /api/cart/items/{id}
GET    /api/cart
```

### Business Rules

* Cannot exceed stock quantity
* Prevent duplicate cart items

---

## 7.6 Order Placement

### Features

* Checkout
* Select payment method
* Generate order number

### APIs

```http
POST /api/orders
GET  /api/orders/my-orders
GET  /api/orders/{id}
```

### Business Rules

* Stock deduction upon checkout
* Transaction rollback if failure occurs

### Important

Use:

* Service Layer Transactions
* Repository pattern

---

## 7.7 Order Tracking

### Seller Actions

Update order status.

### APIs

```http
PUT /api/orders/{id}/status
```

### Allowed Flow

```text
ORDER_RECEIVED
→ ACCEPTED
→ PREPARING
→ SHIPPED
→ DELIVERED
```

### Design Pattern

Use Strategy Pattern for:

* Order status transitions
* Payment processing

# 16. MVP Definition of Done

The MVP is complete when:

✅ User can register/login
✅ User can be verified
✅ Seller can post listings
✅ Buyer can browse listings
✅ Buyer can add to cart
✅ Buyer can place order
✅ Seller can manage orders
✅ Admin can moderate users/listings
✅ Basic security implemented
✅ System deployable locally

# 17. Recommended Simplifications for Academic Success

To ensure stable delivery:

## Avoid for MVP

* Microservices
* Real-time sockets
* AI moderation
* Complex recommendation systems
* Multiple payment gateways
* Mobile app

## Prefer

* Monolith architecture
* REST APIs
* Simple relational database
* Basic admin moderation
* Manual workflows

This increases:

* Stability
* Maintainability
* Faster completion
* Easier demonstration during defense/project presentation
